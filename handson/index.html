CBT Technology Institute, networking program

Lab: routed network with VLANs, DHCP, and dynamic routing

Build it in Cisco Packet Tracer first, then rebuild it in groups on real equipment in the IT lab.

Overview

In this lab you design and configure a network of three routers and three switches. Each router serves one /24 network that you split into two subnets, and the routers connect to each other over serial links. You will first build and test the full design in Cisco Packet Tracer. After your Packet Tracer file is approved, your class will split into groups and build the same network on physical Cisco hardware in the IT lab.

Learning objectives

  • Subnet a /24 network into two equal subnets and identify the usable range, broadcast address, and last valid host.
  • Configure VLANs, access ports, and an 802.1Q trunk on a Cisco 2950 switch.
  • Configure router-on-a-stick subinterfaces so one router port serves two subnets.
  • Build a DHCP pool for each subnet and exclude the gateway addresses.
  • Route between networks using static routes, EIGRP, and single area OSPF, then compare the results.
  • Transfer a Packet Tracer design to physical equipment and coordinate a shared configuration with other teams.

Part 1: addressing, switching, and DHCP

Design requirements

  • R2 connects to R1 on Serial0/0/0 using 10.1.1.0/30 and to R3 on Serial0/0/1 using 10.1.1.4/30. R1 and R3 use their own Serial0/0/0.
  • Each router connects from Gig0/1 to port 24 on its switch.
  • Network 1 (192.168.10.0/24), Network 2 (192.168.20.0/24), and Network 3 (192.168.30.0/24) must each be divided into two equal subnets.
  • On every switch, ports 1 to 8 belong to the first subnet and ports 9 to 16 belong to the second subnet.
  • The default gateway of each subnet is the last valid host address in that subnet.
  • Each subnet needs its own DHCP pool on the router, and PCs must receive their addresses from DHCP.

Design hint

Two subnets share one cable between the router and the switch. Think about how the switch can keep the two groups of ports separate, and how a single router port can hold two gateway addresses. Your answer should involve VLANs, a trunk, and subinterfaces.

Part 1 checkpoint

Before moving to Part 2, every PC should show a DHCP address from the correct subnet and should ping its own default gateway. PCs will not reach other networks yet, and that is expected.

Part 2: routing between the networks

Configure routing three separate ways. Finish one method, test it, record your results, and then remove it completely before starting the next one.

OrderMethodRequirement
1Static routingEvery router must reach every remote network. Keep the number of routes as small as you can and be ready to explain your choices.
2EIGRPUse autonomous system 100, disable automatic summarization, and stop routing updates from being sent toward the PCs.
3OSPFUse a single area (area 0), assign router IDs 1.1.1.1, 2.2.2.2, and 3.3.3.3, and stop hellos from being sent toward the PCs.
After eachVerificationFill in the connectivity test matrix below, then remove the method.

Why removal matters

Leftover routes break the next method. A static route has an administrative distance of 1, EIGRP has 90, and OSPF has 110, so any static route you forget will hide the dynamic routes you are trying to test. Check show ip route after each removal.

Hardware phase: building the network in the IT lab

Once your Packet Tracer file is complete and approved, the class splits into groups. Each group owns one router, one switch, and the PCs behind them. The groups build their sections at the same time and then connect the serial links so the whole network runs as one.

GroupEquipmentResponsibilities
Group AR1, SW1, Network 1 PCsConfigure Network 1 and the R1 side of the R1 to R2 link.
Group BR2, SW2, Network 2 PCsConfigure Network 2 and the R2 side of both serial links. Group B sets the clock rate because R2 holds the DCE end of each cable.
Group CR3, SW3, Network 3 PCsConfigure Network 3 and the R3 side of the R2 to R3 link.
All groupsSerial cables, test PCsAgree on the routing parameters, connect the serial links, run each routing method, and complete the test matrix together.

Hardware steps

  1. Connect to your router and switch with a console cable and a terminal program (PuTTY or similar) set to 9600 baud, 8 data bits, no parity, 1 stop bit.
  2. Clear old configurations. On the router run erase startup-config and reload. On the switch also run delete flash:vlan.dat before reloading, because VLANs are stored separately from the configuration.
  3. Run show ip interface brief and confirm the real interface names. If the serial module sits in a different slot than in Packet Tracer, the names will change (for example Serial0/1/0), and you must adjust your commands.
  4. Cable your section. On R2, run show controllers serial 0/0/0 and show controllers serial 0/0/1 to confirm the DCE cable end is attached before setting the clock rate.
  5. Apply your Part 1 configuration from your Packet Tracer work and complete the Part 1 checkpoint inside your own group.
  6. Meet with the other groups to confirm matching routing parameters, then connect the serial links and complete Part 2 one method at a time.
  7. Take the required screenshots listed under what to submit as you finish each step. Screenshots cannot be recreated after the equipment is erased.
  8. When finished, erase the configurations, delete vlan.dat on the switches, and return all cables to where you found them.

Coordinate before you connect

Your group can configure its own section perfectly and the network will still fail if the groups do not agree on the details. Before connecting cables, confirm serial addresses on both ends of each link, the EIGRP autonomous system number, the OSPF area, and the router IDs.
